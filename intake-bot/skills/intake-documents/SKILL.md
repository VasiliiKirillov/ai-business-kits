# Документы из шаблона

## Когда использовать

Когда по подтвержденной заявке бот должен подготовить документ: договор аренды, договор оказания услуг, квитанцию, лист заказа. Если документ не нужен, поставь `documents.engine: none` и пропусти этот скилл.

## Что нужно от человека

- Текст договора или образец документа. Текст договора предоставляет владелец. Ты не юрист и не пишешь юридические тексты.
- Какие реквизиты бизнеса должны быть в документе (название, адрес, подпись): они пойдут в `documents.constants`.
- Если Google Docs: доступ Google (см. `intake-data-integration`).

## Шаги

Перед каждым шагом коротко объясни человеку, что делаешь и зачем.

1. Спроси, нужен ли документ и какой. Выбери движок:

| Движок | `documents.engine` | Когда |
|---|---|---|
| локальный Word-файл | `docx` | проще всего, не нужен Google; менеджер получает файл в Telegram |
| Google Docs | `google_docs` | документ живет в Google, удобно делиться ссылкой |
| нет | `none` | документ не нужен |

2. Скажи прямо: "Я не юрист. Текст договора мне даете вы или ваш юрист, я только подставлю в него данные заявки."
3. Настрой секцию `documents` в `config/business.yaml`:
   ```yaml
   documents:
     engine: docx
     docx_template: "templates/contract.docx"
     output_dir: "output"
     title: "Договор {booking_id} - {client_name}"
     constants: {COMPANY: "<название>", DEPOSIT: "<сумма>"}
   ```
4. **Движок docx.** Сгенерируй стартовый шаблон из конфига:
   ```bash
   cd ~/intake-bot && .venv/bin/python tools/make_docx_template.py config/business.yaml
   ```
   Без аргумента берется `BUSINESS_CONFIG` или `config/business.yaml`. Скрипт создает `templates/contract.docx` со всеми плейсхолдерами и **перезаписывает** этот файл: если владелец уже правил шаблон, сначала сделай копию (`cp templates/contract.docx templates/contract.backup.docx`). Открой его владельцу (или покажи путь), пусть заменит текст на настоящий договор в Word, сохраняя плейсхолдеры.
5. **Движок Google Docs.** Создай документ-шаблон в Google Docs (сначала поставь Google-зависимости: `uv pip install --python .venv/bin/python -r requirements-google.txt`; затем можно загрузить `templates/contract.docx` как Google Doc: `.venv/bin/python tools/setup_google_sheet.py --upload-template` сделает это и напечатает `GOOGLE_DOC_TEMPLATE_ID`), расставь плейсхолдеры, возьми id документа из адреса (часть между `/d/` и `/edit`) и впиши в `.env`:
   ```
   GOOGLE_DOC_TEMPLATE_ID=<template-doc-id>
   ```
   Бот копирует шаблон через Drive и заменяет плейсхолдеры (`replaceAllText`). Нужны Google OAuth и API Docs, Drive: [shared/google-workspace](../../../shared/google-workspace/SKILL.md).
   Важно: доступ у бота только `drive.file`, то есть к файлам, которые создал он сам. Документ, созданный владельцем вручную в Google Docs, бот скопировать не сможет (ошибка 404 File not found). Поэтому шаблон загружай через `setup_google_sheet.py --upload-template`, а правь его потом прямо в Google Docs, это можно. Широкий доступ ко всему Drive не проси без нужды.
6. Протестируй рендер (см. Проверка).
7. Покажи владельцу сгенерированный документ, получи правки текста, обнови шаблон.

## Плейсхолдеры

Формат `{{ИМЯ}}`. Поддерживаются:

- `{{BOOKING_ID}}`: номер брони
- `{{DATE}}`: сегодняшняя дата
- `{{CLIENT_NAME}}`, `{{CLIENT_CONTACT}}`, `{{CLIENT_PHONE}}`
- `{{ITEM}}`: выбранная позиция
- `{{PRICE}}`, `{{TOTAL}}`, `{{CURRENCY}}`
- `{{DATE_FROM}}`, `{{DATE_TO}}`
- по плейсхолдеру на каждый ключ поля заявки, в верхнем регистре (поле `delivery` дает `{{DELIVERY}}`)
- `{{DOC_FULL_NAME}}`, `{{DOC_NUMBER}}`, `{{DOC_NATIONALITY}}`, `{{DOC_BIRTH_DATE}}`: данные документа клиента (если включено)
- константы из `documents.constants` (например `{{COMPANY}}`, `{{DEPOSIT}}`)

Если значения нет, подставляется `________`, чтобы документ можно было дозаполнить от руки.

## Правка шаблона в Word

Объясни владельцу:

- Плейсхолдер набирай целиком, одним движением, не вставляй по частям.
- Не меняй форматирование внутри плейсхолдера (не делай половину жирным, не меняй шрифт посреди). Иначе Word разобьет его на куски, и подстановка может не сработать. Движок docx старается склеивать такие куски, но надежнее не рисковать.
- Форматируй весь плейсхолдер целиком, если нужно.
- Плейсхолдеры работают в обычных абзацах, таблицах, колонтитулах.
- Лишний плейсхолдер, которого бот не знает, останется в тексте как есть. Это подсказка, что имя набрано с ошибкой.

## Проверка

1. Прогони сценарий с документом на моках:
   ```bash
   .venv/bin/python tests/run_scenarios.py
   ```
   В сценарии есть `expect_document: true`.
2. Консольный режим с тестовой заявкой: `.venv/bin/python -m intake --console`, пройди диалог до итога, подтверди, `/confirm`. В `output/` появится документ (для Google Docs будет ссылка).
3. Открой документ, проверь, что все плейсхолдеры подставились, нет остатков `{{...}}`, цифры сходятся с итогом.
4. Удали тестовые документы: `.venv/bin/python tools/cleanup_test_data.py` покажет, `.venv/bin/python tools/cleanup_test_data.py --apply` отменит тестовые брони и удалит сгенерированные документы). Проверь, что в `output/` и в Google Drive не осталось тестовых файлов.

## Подводные камни

- Ты не юрист. Не сочиняй юридические формулировки, не советуй "достаточно такого текста". Текст предоставляет владелец или юрист.
- Плейсхолдеры, разбитые форматированием, не подставятся. Если подстановка не сработала, пересоздай плейсхолдер: сотри, набери заново без смены стиля.
- Ошибки рендера не блокируют бронь: бот сообщит менеджеру "не смог сформировать документ" и запишет бронь. Проверяй логи после теста.
- Персональные данные клиентов в `output/` не должны попадать в репозиторий: папка в `.gitignore`.
- Всегда чисти тестовые документы. В Google Drive они копятся и засоряют диск владельца.
- Пустые значения дают `________`: убедись, что обязательные для договора поля заявки действительно собираются.
- Google Docs: не ломай шаблон, на каждую бронь создается копия. Права на папку проверь у владельца.
- Стиль: в тексте договора допустимо все, что решит юрист. Правила про буквы и тире из AGENTS.md относятся к сообщениям бота и конфигу, не к договору.
