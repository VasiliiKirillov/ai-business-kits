# Сборка бота из шаблона

## Когда использовать

После онбординга (есть черновик `config/business.yaml`). Это основной скилл про сам код бота: копирование шаблона, настройка окружения, тесты, тонкая настройка тона и фактов.

## Что нужно от человека

- Токен бота от @BotFather.
- Telegram-группа менеджера (куда придут карточки), в нее нужно добавить бота.
- Ключ API провайдера LLM (официальный, с оплатой по использованию).
- Фото позиций (по желанию).

## Шаги

Перед каждым шагом объясни человеку, что делаешь и зачем, одной-двумя фразами.

### 1. Рабочая папка

```bash
mkdir -p ~/intake-bot && cp -r <путь-к-репозиторию>/template/. ~/intake-bot/ && cd ~/intake-bot
rm -rf .venv   # если в template/ случайно был .venv, не берем его
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -r requirements.txt
```

`<путь-к-репозиторию>` - папка, куда склонирован этот репозиторий (скиллы могут лежать в `~/.claude/skills`, а `template/` остается в клоне). Нет uv: `curl -LsSf https://astral.sh/uv/install.sh | sh`. Python 3.11-3.13 подойдет, системный `python3` не используй. Все Python-команды запускай как `.venv/bin/python ...` (каждая команда агента идет в новой оболочке, `activate` не сохраняется).

Если данные в Google, еще `uv pip install --python .venv/bin/python -r requirements-google.txt`. Если папка уже есть после онбординга, не копируй заново и не перезаписывай `config/business.yaml`.

### 2. Конфиг

`config/business.yaml` создан в онбординге. Если нет, вернись в `intake-onboarding`. Проверь:

```bash
.venv/bin/python tools/check_config.py config/business.yaml
```

### 3. Токен бота

Объясни: "Бот в Telegram создается через специального бота @BotFather, он выдает токен, как пароль от бота."

1. Человек открывает @BotFather в Telegram, отправляет `/newbot`, выбирает имя и username (на конце `bot`).
2. BotFather присылает токен вида `123456:ABC...`. Человек вписывает его в `.env` сам.

### 4. .env

```bash
cp .env.example .env && chmod 600 .env
```

Заполни (значения вписывает человек, либо ты, не печатая их в чат):

```
BOT_TOKEN=<your-bot-token>
MANAGER_CHAT_ID=<group-chat-id>
LLM_PROVIDER=anthropic
LLM_API_KEY=<your-api-key>
LLM_MODEL_PARSE=<model-name>
LLM_MODEL_CHAT=<model-name>
```

`LLM_PROVIDER`: anthropic, openai, deepseek, openrouter, ollama или custom. `LLM_MODEL_PARSE` - быстрая дешевая модель для разбора, `LLM_MODEL_CHAT` - модель для ответов. `LLM_PROXY=http://<proxy-host>:<port>` добавляй, только если сервер в геоблоке (см. `intake-server-setup`). Комментарии в `.env` пиши только отдельной строкой, не после значения.

Имена моделей проверь у провайдера: они меняются. Если оставить пустыми, возьмутся значения по умолчанию, но все равно сверься с актуальным списком моделей провайдера. Нужен официальный API-ключ, не подписка.

### 5. Группа менеджера и MANAGER_CHAT_ID

1. Человек создает группу в Telegram, добавляет менеджеров и бота.
2. Чтобы узнать id, достаточно в `.env` иметь `BOT_TOKEN` и `LLM_PROVIDER=mock`. Запусти `.venv/bin/python -m intake` и попроси написать в группе `/id`. Бот ответит числом (для групп оно обычно отрицательное). Это `MANAGER_CHAT_ID`. Останови бота Ctrl+C.
3. Впиши id в `.env`.
4. Чтобы бот видел обычные сообщения менеджера в группе (кнопка "Отвечу сам", дальше менеджер пишет текст клиенту), отключи боту режим приватности: в @BotFather `/setprivacy` -> выбрать бота -> `Disable`. Потом удали бота из группы и добавь заново (настройка применяется при добавлении). Другой вариант - сделать бота администратором группы.
5. Если группу потом превратили в супергруппу (это бывает само, например при включении истории для новых участников), id меняется: снова `/id` и обнови `.env`.

### 6. Тесты на моках (без ключей и сети)

```bash
.venv/bin/python tests/run_scenarios.py
```

Должно быть PASS на всех сценариях. Если нет, разберись до перехода дальше.

**Эти PASS проверяют код и примеры, а не твой конфиг.** Готовые сценарии лежат под примерами (`business.example`, `nail-studio`, `cake-orders`), твой `config/business.yaml` они не трогают.

### 6а. Свой сценарий под твой конфиг

Создай `tests/scenarios/business/01_happy.yaml` с `config: config/business.yaml`. В сценарии `parse:` - это то, что LLM "извлекла бы" из реплики клиента (мок-LLM подставляет его как есть), а чат-мок отвечает "[бот] <статус>", поэтому ты проверяешь решения кода: что спросил, какая цена, ушла ли карточка. Ключи в `parse:` и названия позиций бери из своего конфига (`request.fields[].key`, `catalog.items[].name`). Даты ставь в 2030 году, данные выдуманные.

Прокат (по дням), поля `item`, `date_from`, `days`, `phone`:

```yaml
config: config/business.yaml
name: "прокат: бронь на 3 дня"
steps:
  - client: "нужен <позиция> с 2030-12-01 на 3 дня"
    parse: {type: request, item: "<Название позиции>", date_from: "2030-12-01", days: 3}
    expect_bot: ["Скажи цену"]
  - client: "+66 00 000 0000"
    parse: {phone: "+66 00 000 0000"}
  - client: "да"
    parse: {confirmed: true}
    expect_card: true
  - manager: confirm
    expect_booking: true
```

Запись на время (slots), поля `item`, `date`, `time`:

```yaml
config: config/business.yaml
name: "запись на время"
steps:
  - client: "хочу на маникюр с покрытием в пятницу в 14:00"
    parse: {type: request, item: "Маникюр с покрытием", date: "2030-12-06", time: "14:00"}
    expect_bot: ["Скажи цену"]
```

Если в конфиге есть еще обязательные поля (телефон, доставка, фото документа), добавь шаги для них по образцу готовых сценариев в `tests/scenarios/`. Запуск только твоих сценариев (аргумент - подстрока пути файла):

```bash
.venv/bin/python tests/run_scenarios.py business/
```

### 7. Консольный режим с настоящей LLM

```bash
.venv/bin/python -m intake --console
```

Ты пишешь как клиент, видишь ответы бота и то, что ушло бы в группу менеджера. Команды: `/confirm`, `/own <текст>`, `/photo <путь>`, `/reset`, `/quit`. Прогони типичный диалог, спроси про цену, про доставку, напиши "Привет", ответь на вопрос не по теме.

Для проверки без ключей: `.venv/bin/python -m intake --console --mock`.

Тестовые брони из консоли попадают в `intake.db` (клиент называется "TEST CLIENT") и занимают позиции. Почисти: сначала посмотри список `.venv/bin/python tools/cleanup_test_data.py`, потом `.venv/bin/python tools/cleanup_test_data.py --apply`. Тестовые брони - те, где имя клиента содержит TEST.

### 8. Тон и факты

Правь `config/business.yaml`, не код:

- `bot.tone`, `bot.tone_examples`, `bot.banned_phrases`, `bot.style`;
- `bot.facts`: только факты, которые бот имеет право говорить;
- `catalog.items[].details`: особенности позиций, о которых бот может рассказать.

После правки: `check_config.py`, консоль, смотри ответы. Покажи владельцу три диалога и попроси оценить тон.

### 9. Фото позиций

Положи в `photos/<ключ>.jpg`, где ключ это название позиции строчными латинскими буквами и цифрами. Подробности в `photos/README.md`. Бот отправит фото при выборе позиции, подпись с ценой строит код.

### 10. Запуск в Telegram

```bash
.venv/bin/python -m intake
```

Напиши боту `/start`. Дальше тесты в `intake-testing-launch`. Для круглосуточной работы `intake-server-setup`.

## Как это устроено внутри

Коротко объясни человеку, если спросит:

- `intake/config.py` читает YAML в строгие модели и сообщает по-русски, какой ключ неверен.
- `intake/prompts.py` генерирует промпты парсера и чата из конфига, в коде нет специфики бизнеса.
- `parser.py`: LLM превращает всю переписку в JSON с полями заявки.
- `core.py`: конечный автомат, решает, что спросить, свободно ли, когда слать карточку.
- `chat.py`: отдельный вызов LLM озвучивает статус, не принимая решений.
- Адаптеры: `messengers/` (Telegram, консоль), `llm/` (провайдеры), `data/` (источник данных), `documents/` (движки документов).

Как добавить:

- **мессенджер** (например WhatsApp): новый файл в `intake/messengers/`, реализующий Protocol `Messenger` из `messengers/base.py`: `send_client`, `send_client_photo`, `send_card`, `notify_manager`, `send_manager_file`, `forward_to_manager`. Подключи в `__main__.py`.
- **провайдер LLM**: `LLM_PROVIDER=custom` с `LLM_BASE_URL` для совместимых с OpenAI API, либо новый класс `Provider` в `intake/llm/`.
- **источник данных**: см. `intake-data-integration`.

## Проверка

- `.venv/bin/python tools/check_config.py config/business.yaml` без ошибок.
- `.venv/bin/python tests/run_scenarios.py`: все PASS, и свой `business/01_happy.yaml` тоже.
- Консольный диалог: бот задает по одному вопросу, называет точную цену из каталога, показывает итог, после "да" и `/confirm` появляется карточка и бронь.
- `/start` в Telegram показывает приветствие из конфига, `/id` в группе возвращает число.
- `.env` с правами `600`.

## Подводные камни

Правила дизайна, которые нельзя ломать:

- Поля парсятся из ВСЕЙ переписки, не из последней реплики, иначе бот теряет "на три дня".
- Логику решает код, чат-модель только озвучивает статус. Не добавляй в промпт чата решения вроде "если все собрано, скажи, что передал менеджеру".
- Один открытый вопрос за раз. Если клиент проигнорировал вопрос, не давить два ответа, затем спросить другими словами.
- Тон: коротко, спокойно, без эмодзи, без "Отлично!", без канцелярита. Настраивается в yaml.
- Не выдумывать характеристики и наличие. Цены точные, из источника данных.
- Карточка менеджеру только после подтверждения итога клиентом. Фото документов идут вместе с карточкой.
- Спам, жалоба, вопрос определяются по первому сообщению. Мат и раздражение на бота не жалоба.
- Официальные API-ключи, не подписочные OAuth-токены.
- Не правь `template/intake/` под одного клиента. Если не хватает возможности, расширяй конфиг или пиши адаптер.
- Модель в продакшене должна быть быстрой: разбор вызывается на каждое сообщение, ставь дешевую быструю модель на `LLM_MODEL_PARSE`.
