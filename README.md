# ai-intake-skills

AI-приемщик заявок для малого бизнеса: прокат, запись к мастеру, заказы, бронирования. Это набор Agent Skills и готовый шаблон Telegram-бота. Ты отдаешь репозиторий своему AI-агенту, говоришь "настрой мне приемщика заявок", и агент по шагам, сам выполняя команды и объясняя каждый шаг, поднимает бота под твой бизнес.

Бот родился как демо для проката байков, но внутри нет ничего про байки: все особенности бизнеса (поля заявки, каталог, цены, правила доступности, тон общения, документ) живут в одном файле `config/business.yaml`.

## Что делает бот

Клиент пишет в Telegram как обычному человеку. Бот:

1. понимает свободный текст и вытаскивает из него поля заявки (что, когда, на сколько, куда, контакты);
2. по одному вопросу за раз спрашивает недостающее;
3. проверяет в твоих данных, свободно ли, и называет точную цену;
4. показывает клиенту итог, клиент подтверждает;
5. отправляет менеджеру в Telegram-группу карточку с кнопкой "Подтвердить";
6. по кнопке собирает документ (договор, квитанцию) из шаблона и записывает бронь в таблицу.

Ничего не придумывает: характеристики, наличие и цены берет только из твоих данных.

## Как это устроено

```
клиент пишет свободным текстом
        |
        v
LLM вытаскивает поля в строгий JSON из ВСЕЙ переписки (не из последней реплики)
        |
        v
КОД решает, что спросить и что свободно: проверка наличия и цен в источнике данных
        |
        v
отдельный вызов LLM только озвучивает статус, который решил код
        |
        v
итог клиенту -> клиент подтверждает
        |
        v
карточка в группу менеджера с кнопкой "Подтвердить"
        |
        v
по кнопке: документ из шаблона + бронь записана в таблицу
```

Главная идея: логику решает код, а языковая модель только говорит. Поэтому бот не врет "передал менеджеру", когда ничего не передано.

Все внешнее подключается адаптерами: мессенджер (сейчас Telegram, WhatsApp можно добавить), провайдер LLM (Anthropic, DeepSeek, OpenAI, OpenRouter, Ollama или свой), источник данных (локальная база, Google Sheets или свой адаптер под Excel/CRM), движок документов (docx, Google Docs, без документа).

## Пример диалога

Данные выдуманные.

```
Клиент: привет, нужен pcx с 20го на неделю
Бот:    Honda PCX 160 - 450 бат в день, на неделю со скидкой 10%. Куда привезти или заберете сами?
Клиент: привезите в центр
Бот:    Телефон или WhatsApp для связи?
Клиент: +66 00 000 0000
Бот:    Нужен паспорт для договора. Пришлите фото или напишите данные.
Клиент: [фото паспорта]
Бот:    Проверьте, все ли верно:
        - Honda PCX 160, 1 шт.
        - 20-27 января, 7 дней
        - доставка: центр
        - итого: 2835 бат
Клиент: да
Бот:    Передал менеджеру, он проверит и подтвердит, обычно минут 15.
```

Менеджер в своей группе получает карточку с фото паспорта и кнопкой "Подтвердить". После нажатия клиент получает подтверждение, а в таблице появляется бронь и готовый договор.

## Как запустить

Скорми этот репозиторий своему агенту и скажи: **настрой мне приемщика заявок**.

### Claude Code

```bash
git clone <url-этого-репозитория> ai-intake-skills
cd ai-intake-skills
claude
```

В открывшейся сессии напиши: `настрой мне приемщика заявок`. Claude Code сам прочитает `CLAUDE.md`, затем `AGENTS.md` и пойдет по скиллам. Папка `skills/` читается как набор скиллов. Если хочешь, чтобы они были доступны из любой папки, скопируй их:

```bash
mkdir -p ~/.claude/skills
cp -r skills/* ~/.claude/skills/
```

Скиллы ссылаются на `template/` в клонированном репозитории (оттуда копируется бот), поэтому клон не удаляй и не перемещай.

Или только для одного проекта: положи их в `.claude/skills/` внутри папки проекта.

### Codex, Cursor и другие агенты

Любой агент с доступом к командной строке. Открой папку репозитория в агенте. Codex и Cursor читают `AGENTS.md` автоматически. Если твой агент этого не делает, напиши ему: `прочитай AGENTS.md в этой папке и действуй по нему, настрой мне приемщика заявок`. Если агент не умеет скиллы, `AGENTS.md` объясняет, как читать их вручную: открыть `skills/<имя>/SKILL.md` и выполнять по пунктам.

## Что понадобится от тебя

- [ ] Аккаунт в Telegram. Токен бота получим у @BotFather (агент подскажет, что нажимать).
- [ ] Ключ API языковой модели: Anthropic, DeepSeek, OpenAI или другой. Нужен именно официальный API-ключ с оплатой по использованию, а не подписка вроде "Pro" или "Plus".
- [ ] Сервер (VPS от 5 долларов в месяц, 1 ГБ памяти достаточно) или твой компьютер для пробного запуска. Круглосуточно бот должен работать на сервере.
- [ ] Аккаунт Google, если данные будут храниться в Google Sheets и Docs.
- [ ] Час-два времени и готовность ответить на вопросы о твоем бизнесе.
- [ ] Telegram-группа для менеджера (создается за минуту).

## Сколько это стоит

Порядок цифр, точные цены смотри у провайдеров:

- сервер: около 5 долларов в месяц (можно не покупать на время теста);
- языковая модель: обычно от нескольких центов до пары долларов в месяц при нескольких десятках заявок в день, зависит от модели; дешевые модели вроде DeepSeek или Haiku заметно экономнее;
- Google Sheets и Docs: бесплатно;
- сам репозиторий: бесплатно, лицензия MIT.

## Структура репозитория

```
AGENTS.md                           инструкция для любого агента: роль, порядок, правила
CLAUDE.md                           отсылка на AGENTS.md для Claude Code
skills/
  intake-onboarding/                интервью с владельцем, получаем config/business.yaml
  intake-server-setup/              VPS, SSH-ключи, пользователь, Python, systemd, прокси, логи
  intake-data-integration/          где хранятся данные: локально, Google Sheets, Excel/CRM, адаптеры
  intake-bot-build/                 запуск шаблона: .env, конфиг, тесты, настройка тона
  intake-documents/                 договор и другие документы из шаблона (docx или Google Docs)
  intake-testing-launch/            тесты, чеклист запуска, чистка тестовых данных, мониторинг
template/                           сам бот: код, примеры конфигов, инструменты, тесты
```

## Чего здесь нет

Нет ничьих персональных данных, токенов, ключей, адресов серверов и ссылок на чужие таблицы. Все примеры выдуманные. Секреты ты вводишь у себя на сервере в файл `.env`, в репозиторий они не попадают.
